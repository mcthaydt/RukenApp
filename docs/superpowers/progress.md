### Known issues

- Opening a game's page with the pointer over its "Made by" link can preload the maker's page (`/<handle>`), which counts one view and sets the arrival cookie without a person opening it. Seen in the review of pull request #249; left as is. A fix would stop the link being preloaded (`data-sveltekit-preload-data="off"` on that link) or count views only on a real open.
- The rule hook reads a pull request's lane from its body and takes the highest "lane N" it finds anywhere (`.claude/hooks/rules.mjs`, `LANE` and `laneOf`), so a body that mentions another change's lane is classed by it. Pull request #252 was lane 2, but its "Not in this pull request" section said the CI change would be "lane 3, its own pull request", so the hook asked for a lane 3 audit before ready (seen 2026-11-21 at 7b67aa5). It did not block: the lane 2 review's "7b67aa5 PASS" satisfied it. Until the hook reads only the lane line, write another change's lane without the word "lane" in a body. A fix is a lane 3 change to the hooks.
- Hook follow-up, a false positive at `.claude/hooks/rules.mjs:1126` (seen 2026-11-21 while writing the apps-kit spec): a local interpreter script (for example `python3`) whose text holds a launcher word (`LAUNCHES_OR_REQUESTS`, line 1107: subprocess, system, exec, spawn, popen, fetch, curl, a backtick and others) together with either the word gh plus a gh subcommand word (`GH_SUBCOMMAND`, line 1108: pr, api, repo, run and others) or the text api.github.com is refused as a GitHub call ("runs a script that calls gh or api.github.com"), even when the script makes none. It looks only at the words. A fix is a lane 3 hooks change of its own; the apps-kit alignment does not change the hook.
- Hook follow-up, a false positive reported on 2026-11-22 by another thread through the coordinator: a test command wrapped in `time` was refused as a possible pull request write. Not traced to its rule here (`rules.mjs:265` strips a leading `time` when reading a command's words, so the refusal comes from another check). A fix is a lane 3 hooks change, for the retrospective's list of hook fixes.
- Hook follow-up, a lane mismatch reported on 2026-11-22 through the coordinator: the hook classes an edit to `.claude/skills/this-repo` as lane 3, while CLAUDE.md Risk ("A repo's own skills") says one edited alone is lane 1 unless it changes what needs the owner. A fix is a lane 3 hooks change, for the retrospective's list of hook fixes.

### Lessons

From the slice 2 retrospective (`docs/superpowers/audits/2026-11-22-slice-2-retrospective.md`, L1 and L5 to L9). Each names its trigger, what to look for and the failure behind it.

- L1. Trigger: merging any pull request. Look for: the merging session ran the queue by hand (`release`, Lanes and merging): merged current `main` in, reran the checks on the result, one pull request at a time, and recorded the three commits in the body. Failure: #276 and #277 merged seven minutes apart without the by-hand queue, each tested without the other, and `main` went red (#281).
- L5. Trigger: a browser journey that opens an address or follows a link straight after another page. Look for: it waits for the page to settle first (`pageHasSettled`). Failure: `pay.test.ts:41`, `adults-only.test.ts:233` and `edit-page.test.ts:80` flaked on an interrupted navigation. Prune once journeys open addresses through one settling helper.
- L6. Trigger: a design round or visual check on a screen that moves (a drag, a swipe, a panel that opens or turns). Look for: the move is checked part way through, in pictures taken during it or a short recording, not only at rest. Failure: the Menu tab pointed the old way mid-drag and the menu opened on the wrong side; three design rounds of still pictures passed it and the owner found it (#265).
- L7. Trigger: a change to a rule's wording (CLAUDE.md, `.claude/skills/`, a spec, `progress.md`). Look for: the brief names the old wording as a search, and its check is that the search finds it nowhere outside History. Failure: old wording left in other files was five of the eight red verdicts on the hooks and apps kit work.
- L8. Trigger: handing a planned unit's branch to its audit. Look for: `git diff --name-only origin/main...HEAD` lists only the files in the unit's row. Failure: unit A failed two audits for files outside its row (G6).
- L9. Trigger: starting any unit of the next slice. Look for: the slice before it has closed, with its retrospective's pull request open or its "nothing to learn" report. Failure: slice 3's plan and four units started while slice 2's walk and design rounds were open, and the owner parked slice 3.
