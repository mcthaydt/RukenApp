- N7. The purge's game update does not take the decision lock (`DECISION_LOCK_KEY`), and `sendOutDecisionDays` reads a game's state and then writes `becomesLive` without a row lock. If a purge commits between that read and write, a deleted maker's waiting game could go live with its files already gone. The window is small and the daily purge (09:17 UTC) and the hourly decision-day job (on the hour) run at different minutes; an at-once staff yes has the same shape. Bounded fix if wanted: take `pg_advisory_xact_lock(DECISION_LOCK_KEY)` at the start of the purge transaction, or `updateMany ... where state: waiting` in the release.
