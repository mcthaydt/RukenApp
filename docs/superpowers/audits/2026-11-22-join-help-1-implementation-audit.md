## Red

### R1. The clip check is flaky

UNIT: `tests/browser/join-and-help-look.test.ts`, "its top has no surface of its own, so the game shows behind the title as clearly as around the card".
VERDICT: red.
REQUIREMENT: CLAUDE.md, Verification: "A test that fails once and passes on retry is a defect".
REASON: the clip is paused as soon as a `<video>` exists, not once it has a frame, so the first reading can be taken before the frame is drawn.
EVIDENCE: at 8d1bc698, computer: `Expected: >= 0.04494557257706445`, `Received: 0.01081740683414936` (line 209). The same test then passed 6 of 6 with `--repeat-each=3`, and passed at ec2fb34e. The card top's computed background is transparent in every run (the earlier assertion passed), so the dark first reading is the clip, not the card. The test waits only on `.behindcard video` having count 1 before `video.pause()`.
EXPECTED: the two readings are taken of the same drawn frame, every run.
FIX: in that test only, wait for the video to have a frame before pausing (for example `expect.poll(() => video.evaluate(v => v.readyState >= 2))`, then pause, then wait for `seeked`/one animation frame), and record it under "Flaky tests" in `progress.md`. Files: `tests/browser/join-and-help-look.test.ts`, `docs/superpowers/progress.md`.
