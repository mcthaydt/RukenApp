## The ring fix (`0960673`)

- CSS: the ring now matches `input:focus-visible`, or `input:focus` inside `.plans[data-keys]`. Tab gives `:focus-visible` in every engine; an arrow key sets `data-keys` through the window keydown, so WebKit's dropped `:focus-visible` after an arrow key is still covered. The CI keyboard test (Tab, then ArrowDown, then polls the ring's outline) passed on the WebKit phone profile.
- Click: `pointerdown` on window clears `data-keys` before the click focuses the radio, and Chromium gives no `:focus-visible` to a clicked radio, so no ring. The new check reads `::before`'s `outlineStyle`; the ring is drawn with `outline: 3px solid`, so on `f41311d` (which matched plain `:focus`) the same check would have read `solid`. The check discriminates.
- Leaks: the listeners are on `<svelte:window>`, which Svelte removes when the page is destroyed. No manual `addEventListener`.
- Owner rules: the delta adds no text, no underlined link and no "Loading..." text.
