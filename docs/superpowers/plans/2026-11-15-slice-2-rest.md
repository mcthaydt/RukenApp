## Found while planning

1. **`workers.dev` is a public suffix, so the test site and the gate are two origins of one site.** The site's cookies are host-only (`src/features/accounts/cookies.ts`), so a game cannot read them, and a game's script cannot read anything from the site. What stops a game's request to the site today: the gate's `connect-src`, the frame's sandbox, SvelteKit's origin check on form posts, and that the site has no `GET` that changes anything. A game can still set a plain-named cookie (`rk_arrival`, `rk_welcome_back`) that the site then receives. So until the games domain exists, only games the Owner trusts are accepted on the test site; Task 24 says so and launch's list carries it.
2. **A game written straight into the database has no files in the bucket.** `fillAnswers` and `putGameWhereStaffLeaveIt` write rows only. A journey that loads a game's files makes its game through the real screens (`submitGame`, Task 30).
3. **The gate is deployed by hand** (`pnpm run deploy:games`); Workers Builds deploys only the site. No task here changes `src/features/play/gate.ts` or `cloudflare/games/`, so the gate on the test site stays as it is.
4. **A real first send is slow in a journey:** 8 to 14 seconds a project (measured on the first attempt's run 43702379831). Journeys make a real game only when they load its files.
5. **A game waiting for its first yes can be neither taken off nor thrown away.** That gap is M's. Reported, not fixed here.
6. **The approved board (`maker-screens-round-7.html`) is not in this project's files.** The spec's words (13.1 M1, M2) and the sketches below are the brief for the two maker screens.

    Its refusals, word for word:
    - no `do`, or one it does not know: `Say what to do: "do" is "list", "look", "accept" or "send-back".`
    - `look`, `accept` or `send-back` with no `game` text: `Say which game: "game" is its address from the list.`
    - `send-back` with no `parts`, an empty list, or an item that is not `{ part, words }` of two texts: `Say what's wrong: "parts" is a list like [{ "part": "files", "words": "It doesn't start." }].`
    - a `part` that is not a `GamePart`: `That part isn't one of: name, one_line, files, plays_on, upright_video, wide_video, age_rating, other_websites.`

    It does not judge the words themselves or which parts a live game allows: the service does, in its own words.
  - `POST /jobs/review`. Anyone without the secret: `error(404)`. A body that is not JSON is read as `{}`. Every answer is `Response.json(…)` written with two spaces of indent, so it reads well in a terminal.
